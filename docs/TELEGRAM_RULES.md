# Telegram Catalog Rules v1 — только собственная группа

## Область действия
- Единственный Telegram-источник: группа пользователя «Пхукет | Каталог недвижимости».
- Не читать, не собирать и не синхронизировать чужие группы/каналы и переписки.
- Никаких автоматических публикаций, массовых переносов, удалений или редактирований существующих сообщений без отдельного подтверждения.
- Правила дополняют `AGENTS.md` и `MEMORY.md` проекта Phuket Atlas; действующие соглашения важнее.

## Цель
Поддерживать удобный брокерский каталог, связывать карточки группы с актуальными материалами Google Drive и, по отдельной задаче, с объектами Phuket Atlas.

## Одна запись на один объект
Хранить внутренний идентификатор, название проекта, район, тип (вилла/кондоминиум), сегмент, ID/ссылку Telegram-сообщения, ссылки на папку застройщика и материалы, дату последней проверки. Для отдельных лотов также фиксировать тип планировки и идентификатор лота, если известен.
- При поступлении данных искать совпадения по идентификатору проекта/лота, ссылкам и названиям; сомнительные совпадения отправлять на проверку.
- Обновления не должны создавать повторные карточки без причины.
- Не подменять один лот другим в пределах одного комплекса.

## Источники и достоверность
- Telegram-группа — интерфейс каталога, не гарантия актуальной цены или наличия.
- Цены, сроки сдачи, площади, статус наличия сверять с официальными файлами застройщика или актуальным Sales Kit, если доступны.
- Хранить ссылку на первоисточник и дату проверки; неподтверждённые значения помечать «требует проверки».
- Не придумывать координаты или точность геометок. Приблизительное положение маркировать отдельно.
- Агентские прайсы, персональные контакты, конфиденциальные материалы не переносить в публичный Atlas.

## Структура каталога
Сохранять утверждённые рубрики по району, ценовому сегменту и типу недвижимости; в частности Laguna / Bang Tao, отдельные виллы и ранее созданные категории. Не перестраивать структуру без запроса.

## Экономия токенов и контроль риска
1. Обрабатывать только новые или изменённые записи, не перечитывать весь каталог без необходимости.
2. Сначала использовать краткий реестр ID и ссылок, затем читать материалы только выбранного объекта.
3. Проверять дубликаты и подтверждённые решения; фиксировать краткий результат, без полной переписки.
4. Перед записью показывать состав изменений, риски и объекты с неоднозначными данными.
5. После подтверждённого изменения проверять ссылки, содержание и расположение карточки; обеспечить журнал для отката.
6. Отчитываться кратко: «Изменено / Проверено / Статус».

## Доступ и технические ограничения
- Чтение и изменение Telegram возможны только при фактически доступном и авторизованном инструменте; доступ не считать предоставленным автоматически.
- Telegram-бот обычно видит новые сообщения лишь при соответствующих правах/настройках и не получает произвольную прошлую историю через Bot API.
- Первоначальный импорт истории требует отдельного разрешённого способа; API-ключи и токены не сохранять в Git.

## Разделение систем
- Telegram: пользовательский каталог сообщений.
- Google Drive: материалы и документы застройщиков с проверкой актуальности.
- Phuket Atlas: карта и фильтры, синхронизация только по отдельной задаче.
