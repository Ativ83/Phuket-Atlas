# Phuket Atlas — обязательные правила для AI-агентов

Перед работой прочитай `MEMORY.md`. Читай лишь относящиеся к задаче документы из `docs/` и нужные участки кода. Не перечитывай весь проект без необходимости.

1. Сохраняй согласованные решения и работающие функции. Не изменяй их без запроса пользователя. Если задача конфликтует с ранее согласованным решением, запроси разрешение.
2. Работай точечно: найди ответственный компонент, оцени зависимости, внеси минимальную правку. Без постороннего рефакторинга.
3. Не делай необоснованных предположений о коде, фактах недвижимости, координатах или ценах. Проверяй первоисточник.
4. Перед существенным изменением обеспечь возможность отката через Git. Проверяй сборку, затронутые функции и регрессии в доступной среде. Непроверенное не называй проверенным.
5. После значимых изменений точечно обнови `MEMORY.md` и релевантные файлы `docs/`. Мелкие правки остаются в Git-истории, а не в памяти.
6. `MEMORY.md` должен быть компактным (ориентир: до 150–200 строк). Не загружай всю документацию на каждую задачу.
7. Не добавляй пароли, API-ключи, токены и приватные данные в Git. Не отключай публичную версию до проверки закрытой и отдельного разрешения.
8. В финале кратко сообщи: «Изменено», «Проверено», «Статус».
9. Важнее экономии токенов: корректность, безопасность, воспроизводимость и сохранность согласованных функций.

Подробности: `MEMORY.md`, `docs/ARCHITECTURE.md`, `docs/DECISIONS.md`, `docs/BUGS.md`, `docs/CHANGELOG.md`, `docs/CURRENT_TASK.md`.

## Облегчённый протокол Atlas v2 (на основе принципов ECC)
1. **Контекст по требованию.** Сначала карта в `MEMORY.md`; дополнительные документы и исходники читать только по необходимости. Не подключать объёмные наборы навыков, агентов и хуков без отдельной задачи.
2. **Проверенные решения прежде новых.** Перед исправлением повторяющейся ошибки искать релевантную запись в `docs/BUGS.md` и `docs/DECISIONS.md`; не повторять неудачные подходы без причины.
3. **Проверка по риску.** Малые изменения — точечная проверка; изменения данных — валидация схемы; UI — проверка затронутого сценария; деплой, авторизация, ключи и критические функции — расширенные проверки перед публикацией. Указывать, что проверено фактически.
4. **Субагенты только по необходимости.** Отдельный AI-аудит допустим для сложных изменений с повышенным риском, если инструмент доступен и польза превышает стоимость токенов. Не запускать субагентов на типовых мелких правках.
5. **Безопасность и объём изменений.** Проверять diff на случайные изменения, секреты и раскрытие агентских материалов. Сторонние скрипты, хуки, навыки и действия с секретами не запускать автоматически без проверки и необходимости.
6. **Экономный итог.** Сохранять только решения, результаты проверки и следующие шаги; не переносить полные логи разговоров. Git остаётся журналом мелких изменений.
7. **Приоритет пользователя.** Этот протокол дополняет ранее утверждённые правила, не отменяет их и не допускает отклонений без явного разрешения пользователя.
